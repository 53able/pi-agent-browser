# Documentation localization policy

This project keeps English as the primary README language and provides Japanese as a first translated README.

The current structure follows patterns observed in trending GitHub repositories via Trendshift:

- `alibaba/open-code-review` places language links at the top of `README.md` and keeps translated files such as `README.ja-JP.md`, `README.zh-CN.md`, and localized `CONTRIBUTING.*.md` files.
- `shiyu-coder/Kronos` places a compact language switcher directly under the project title and links to multiple translated README variants.
- `mattpocock/skills`, `earendil-works/pi`, `likec4/likec4`, and `block/buzz` keep the main README focused on the strongest user path; this is useful even when a project later adds translations.

## File naming

Use locale-suffixed Markdown files at the repository root for user-facing README translations:

```text
README.md          # English, default for GitHub and npm
README.ja-JP.md    # Japanese
```

Use locale-suffixed files under `docs/` for maintainer documentation:

```text
docs/project-history.en.md
docs/project-history.ja-JP.md
docs/project-history.md       # language index
```

## README language switcher

The top of each README should include a short language switcher:

```md
English | [日本語](README.ja-JP.md)
```

Japanese README:

```md
[English](README.md) | 日本語
```

Keep this near the title so readers can switch before scanning installation instructions.

## Translation scope

Translate user-facing material first:

- what the package does
- installation
- registered tools
- common workflows
- safety guidance
- troubleshooting

Maintainer-only material can live in `docs/` and should be translated when it affects contribution or release work.

## Maintenance rule

When changing user-facing README content, update both `README.md` and `README.ja-JP.md` in the same pull request. If a section exists in only one language, make that explicit rather than leaving readers to guess whether the other file is stale.
